# 출시 품질 승인 매트릭스 — 체크리스트 v3 전 항목

> 대상: 「보리의 폐품 로켓 대소동 상용 출시 품질 기획 체크리스트」 구현 감사 개정판 3 (2026-10-02)
> 기준 코드: `c6f251f` (main 작업 트리, 2026-10-02). 웹 프로토타입(Vite + TypeScript + three.js + planck). Android 프로젝트·스토어·광고/결제 SDK·서버 없음.
> 작성 방식: 모든 "구현 확인"은 소스를 직접 읽거나 검색해서 확인했다. `npx vitest run`(21개 통과)과 `vite build --mode single`(글꼴 내장·`check:release` 통과)은 이 문서 작성 중에 직접 실행했다. **Playwright E2E(`e2e/*.spec.ts`)는 이 문서 작성 중에 실행하지 않았다.** E2E를 근거로 든 항목은 CI 실행 기록(`test-results/e2e.json`, GitHub Actions 로그)을 붙여야 근거가 완성된다.
> "(문서)"는 같은 커밋의 `docs/*.md` 설계 문서다. 문서가 있다는 것만으로는 동작 증거가 되지 않는다.

**승인 0건.** 이 문서의 어떤 항목도 `승인`이 아니다. 승인에는 담당자, 시험 빌드, 기기·입력·결과 증거와 사람의 확인이 필요하다(체크리스트 0장). AI 자기평가, 자동 시험 통과, 문서 작성만으로는 승인하지 않는다.

## 상태 정의 (체크리스트 0장의 용어)

| 상태 | 이 문서에서 쓰는 뜻 |
|---|---|
| 미구현 | 동작·산출물이 없거나, 항목의 핵심 요구 중 AI가 지금 만들 수 있는 부분이 아직 없다. 일부만 있으면 근거 칸에 "(부분)"으로 적는다. |
| 구현 확인 | 요구한 동작이 코드에 있고 파일·함수로 확인했다. 자동 시험이 있으면 시험 이름을 적고, 없으면 "자동 시험 없음"이라고 적는다. 출시 승인은 아니다. |
| 코드 위험 | 코드를 읽어 찾은 결함·위험이다. 실제 사용자에게 재현되지는 않았다. |
| 실물 재현 | 실제 빌드에서 재현한 결함이다. 이번 감사에서 새로 재현한 것은 없다(R-01 원래 재현은 수정 후 회귀 시험으로 대체). |
| 검증 대기 | 구현되었거나 일부 구현되었지만, 합격에 AI가 만들 수 없는 증거가 필요하다. 실기기, 처음 보는 사용자, 플레이테스트, 청취·아트 검수, 스토어·법무, 실제 SDK, 소프트런치 데이터, 오너 결정 같은 것이다. 무엇이 빠졌는지 적는다. |
| 승인 | 사용하지 않는다(0건). |
| 비대상 | 이 웹 프로토타입 범위에서 일부러 뺀 후보 기능이다. 이유와 "승인자: 게임 오너(미정)"를 적는다. 오너가 승인하기 전까지는 제안일 뿐이다. 핵심 약속·필수 품질은 비대상으로 두지 않았다. |

여러 상태가 섞인 항목은 가장 앞선 단계로 기록했다. 순서는 미구현 > 코드 위험 > 검증 대기 > 구현 확인이다. 예를 들어 실기기가 필요하지만 AI가 할 수 있는 시험도 안 한 항목은 `미구현`이다.

## 출시를 막는 것 (그룹별)

**A. 코드에서 찾은 위험 — 먼저 고칠 것 (AI가 바로 처리 가능)**
1. **퇴장(escape) 중 일시정지 → "그만하고 나가기"/"처음부터 다시"를 고르면 성공이 실패로 정산된다.** `Flight.abandon()`이 `finish(false, true)`를 부른다(`src/game/flight.ts` abandon). 목표는 이미 부서졌는데도 공략·첫 성공 보상·`cleared`가 저장되지 않는다. `docs/spec-core.md` §2(문서)에는 "퇴장 중 일시정지·나가기는 성공 정산"이라고 적혀 있어 **문서와 코드가 다르다.** (C-097, C-166, Q-AH-08, Q-PH-08, Q-QA-04)
2. **퇴장 7초 동안 앱 프로세스가 끝나면 성공이 사라진다.** 성공 정산은 `finish(true)`(퇴장 종료 후)에서만 저장된다. `visibilitychange`는 일시정지와 저장만 하고 성공을 확정하지 않는다. (C-176, C-099)
3. 오디오 보이스 상한 `BUDGET.voices = 18`은 선언만 있고 어디서도 적용되지 않는다(`src/core/audio.ts`는 키별 간격 제한과 컴프레서만 쓴다). (Q-PF-03, Q-VF-04, C-129)
4. `html, body { touch-action: none }`(`src/ui/style.css:19`)이면 모바일에서 핀치 확대가 막힐 수 있다. R-11 E2E는 viewport meta만 검사한다. (R-11, Q-UX-09)
5. HUD 일시정지 버튼이 40 CSS px다(`style.css:221`). 프로젝트 시작값 48dp보다 작다. (Q-UX-03)
6. 목표 화살표는 직선 방향만 가리켜서 벽 너머 직진을 유도할 수 있다(`ui.setTarget`). (C-059, Q-CA-05)
7. 프레임당 물리 5단계를 넘는 시간은 버린다(약 12 FPS 미만이면 게임 시간이 느려진다). (C-035, Q-PF-09)
8. 잔해 상한(90)을 넘으면 가장 오래된 잔해가 화면에서 즉시 사라진다(`world.spawnDebris`). (C-051)
9. 코인 자석이 벽을 무시하고 병뚜껑을 끌어온다(`world.ts` 픽업 갱신). 의도인지 정의되지 않았다. (C-081)
10. 자원 수명(R-07): 정리 코드와 `e2e/longrun.spec.ts`(재시도·장착 100회)는 새로 생겼지만 실행 결과가 없다. 30분 연속·무대 왕복은 다루지 않는다.
11. 회귀 시험이 없는 R 항목: R-03, R-06(복합 연쇄), R-09. R-10은 통합 시험 없이 순수 함수 단위 시험만 있다. (Q-QA-07)

**B. 실기기·성능**: 최저/중급/고급 Android 기기 선정, 최대 난장판 60 FPS(P95/P99), 30분 열·메모리, 입력 지연(Q-IN-10 출발값 P95 80 ms), 30/60/고주사율 물리 대조, 노치·안전영역·시스템 제스처, 멀티터치·손바닥·OS 터치 취소, 백그라운드·전화·오디오 장치 전환, 콜드 시작·재시도 시간. 지금 있는 숫자(그리기 호출 253 ≤ 260, CPU 갱신 p99 ≈ 6.7 ms)는 CI 서버(SwiftShader)의 카운터일 뿐 기기 성능이 아니다.

**C. 사용자 시험**: 처음 보는 사용자 관찰(목표·추력 켜짐/꺼짐·실패 원인 설명, 충돌/통과 예측 Q-CI-07, 첫 연구 체감), 재미·자발 재도전(Q-FU), 좌우손 엄지 조작, 읽기 보조(스크린리더)·글자 200 %·색각, 광고 시청 기대와 실제 플레이 비교(Q-AH-10), 게임 오너·독립 검토자의 직접 플레이 승인(Q-FU-08, Q-QA-10).

**D. 스토어·정책·법무**: 배포 형태(웹 vs Android) 결정, Android 패키지·AAB·서명·API 36·16 KB 페이지, 테스트 트랙, 타깃 연령·Families·IARC, 개인정보처리방침·데이터 안전성, 자산·글꼴·이름 라이선스 원장, 지원 연락처.

**E. 수익화**: 수익화 모델이 정해지지 않았다. 광고·IAP·보상 지급·환불·복구는 하나도 구현되지 않았다(이 문서에서는 비대상 제안). 공개 출시에서 수익화를 채택하면 C-232~C-245, C-274, Q-OP-04 전체가 필수로 돌아온다.

**F. 운영·계측 백엔드**: 이벤트는 기기 안 링 버퍼(`src/core/telemetry.ts`)에만 남고 전송·SDK·동의·대시보드가 없다. D1/D7 정의서, 실험 체계, 소프트런치 게이트, 크래시·ANR 수집, 장애 대응·고객지원·원격 설정·롤백도 없다.

**G. 아트·사운드 최종 검수**: 아트 바이블, 캐릭터 연기·전환 검수, 재질별 효과음 청취(실기기 스피커·이어폰), 믹싱, UI 이모지 의존(플랫폼마다 모양이 다름, Q-AR-08), 참고작 비교 리뷰.

**H. 콘텐츠·경제 검증**: 12개 공략과 20개 톱니는 자동 조종(정상 포인터 입력)으로만 확인했다. 사람 플레이 영상, 투자 순서 시뮬레이션, 실패 파밍 효율, 실제 진행 속도·소진, 무대3 기본 기체의 연료 여유(`docs/economy.md` 열린 질문)가 남았다.
