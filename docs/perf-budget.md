# 성능 예산 (Q-PF)

> 상태: **구현 확인(예산·상한·스트레스 시험)** / **검증 대기: 실기기 60 FPS**(최저/중급/고급 기기 선정, P95/P99, 30분 열 저하, 입력 지연). 헤드리스 CI는 소프트웨어 GL이라 프레임 시간이 기기 성능을 뜻하지 않는다.

## 예산 (`src/game/budgets.ts`)
| 항목 | 예산 | 강제 방식 |
|---|---|---|
| 프레임 | 16.7 ms (60 FPS) | 실기기 측정 필요 |
| 물리+게임 갱신 | 4 ms (중급 폰 목표) | CI 회귀 감시: p95 < 8 ms, p99 < 16.7 ms (공유 서버라 꼬리 지연은 잡음이 큼) |
| 그리기 호출 | ≤ 260 (최악 장면, 고품질) | 스트레스 시험 단언 |
| 깨어 있는 동적 물체 | ≤ 300 (물·잔해 포함) | 잠자기 + 상한 |
| 잔해 | ≤ 90 (순간 최대 102) | 90을 넘으면 오래된 조각이 0.3 s에 걸쳐 작아지며 사라지고, +12에서만 즉시 회수; 재질별 인스턴스 1회 그리기 |
| 물방울 | ≤ 160 | 서로 충돌하지 않음, 오래된 것부터 회수 |
| 파티클 | ≤ 1600 (저품질 800) | 전역 예산, 오래된 것부터 재사용 |
| 링 효과 | 동시 8개 | 오래된 것부터 회수 |

## 적용한 최적화
- 정적 장식·깨지지 않는 구조: 재질별 병합(`bakeStatic`).
- 소품 모델: 단계 마무리 때 재질별 병합(`mergeByMaterial`), 아이 모델은 관절별 병합(`mergeRig`).
- 기본 블록·깨지는 판·잔해: 재질별 `InstancedMesh`.
- 충돌 윤곽선: 역할별 한 메시로 매 프레임 갱신(`OutlineBatch`), 금: 인스턴스 2개.
- 작은 소품(면적 < 2.5 m²)·배경 인물: 그림자 안 드리움.
- HUD 초상화 아이: 작은 텍스처에 20 Hz로 그리고 매 프레임 사각형 하나로 합성.
- 저품질: 블룸 끔, 픽셀 비율 ≤1.25, 파티클 예산 절반. 자동 전환(3 s 동안 32 FPS 미만 두 번) 시 안내.
- **줄이지 않는 것**: 충돌체, 창문·통로, 연쇄 기믹, 목표, 물리 시간(고정 60 Hz, 시간 버림은 프레임당 5단계 초과분만).

## 스트레스 무대 (`src/dev/stress.ts`, 시험 빌드 전용)
실제 생일파티 집 + 선물 상자 18개·유리 6개·축포 2개·물탱크·도자기 접시 10개·부엌 불·창밖 선물산 16개. `e2e/perf.spec.ts`가 정상 입력으로 침입→축포→2층→계단→1층을 비행하며 매 프레임 갱신하고 6프레임마다 그린다.

| 측정 (CI, 2026-10-02) | 최적화 전 | 후 |
|---|---|---|
| 그리기 호출 최대 | 568 | 253 |
| 갱신 p95 / p99 | 7.3 / 8.9 ms | 4.6 / 6.7 ms |
| 깨어 있는 물체 최대 | 290 | 184 |
| 부순 물체 | 46 | 46 |

## 측정 방법 (실기기)
1. `npm run build:test` 결과물을 기기에서 열고 주소에 `?perf`를 붙인다 → 왼쪽 아래 FPS·p95·p99·그리기·물체·파티클 표시.
2. 스트레스: 개발자 콘솔 `__jrr.stress()` 후 실제 손으로 같은 경로 비행, 또는 무대2 축포 공략.
3. 30분 연속(재시도 반복)으로 열 저하·메모리 추세 기록. 결과를 이 문서와 승인 매트릭스에 기기명과 함께 남긴다.
