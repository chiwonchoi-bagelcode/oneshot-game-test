# QA 계획과 자동화 원칙

## 자동화 원칙 (체크리스트: 강제 성공·순간이동·상태 주입·재화 주입은 증거가 아니다)
- 시험 훅(`src/dev/testhooks.ts`)은 **시험 빌드에만** 들어간다(`VITE_TEST_HOOKS=1`). 출시 번들 검사 `npm run check:release`가 훅 이름이 없음을 확인한다.
- 입력은 실제 DOM 경로: `PointerEvent`를 `elementFromPoint`로 찾은 요소에 보낸다(대화상자가 가리면 입력도 막힘). 버튼은 보이고 눌리는 경우에만 누른다(`press`).
- 시간: 브라우저 루프와 같은 고정 60 Hz 갱신을 `advance/step`으로 진행(헤드리스 소프트웨어 GL이 느려서). 순간이동·속도 설정·상태 쓰기는 하지 않는다.
- 사전 조건만 저장 고정값으로 준다(무대 잠금 해제, 부품 보유). 테스트 이름에 `[fixture: …]`로 밝힌다. 결과(공략·톱니·병뚜껑)는 절대 주입하지 않는다.
- 게임 난수는 (무대, 시도) 시드라 같은 입력 → 같은 결과.

## 사람이 해야 하는 검수 (자동화가 대신할 수 없음 — 승인 매트릭스 "검증 대기")
1. **실기기**: 최저/중급/고급 Android 기기 선정 → 스트레스 무대·무대2 축포 60 FPS, P95/P99, 30분 열·메모리, 터치 지연(`?perf` 오버레이).
2. **처음 보는 사용자 관찰**(5명 이상): 설명 없이 목표·추력 켜짐/꺼짐·실패 원인을 말하는지, 정지 화면에서 부딪힐 것/통과할 곳/깰 입구 표시(Q-CI-07), 첫 연구까지 시간.
3. **엄지 조작**: 좌우손·노치·작은/큰 화면·시스템 뒤로가기 제스처, 글자 확대, 화면 읽기 프로그램.
4. **광고 가설**: AH-1 영상 시청 기대 vs 실제 플레이 평가(Q-AH-10).
5. **스토어·정책·법무**: 패키지·서명·연령 등급·개인정보·광고/결제 SDK(미선택).

## 회귀 순서 (최적화·콘텐츠 변경 뒤, Q-PF-10)
`npm run ci` 전체 → 스트레스 결과(`test-results/perf-stress.json`)를 `docs/perf-budget.md` 표와 비교 → 무대별 스크린샷 육안 확인.
