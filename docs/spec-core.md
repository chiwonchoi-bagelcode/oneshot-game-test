# 핵심 규칙 명세 (spec-core)

> 상태: **구현 확인**(코드·자동 시험) — 수치는 초기값이며 사용자·실기기 체감 승인 전이다.
> 기준 코드: `src/game/flight.ts`, `src/core/input.ts`, `src/game/rocket.ts`, `src/game/world.ts`.

## 1. 한 판의 상태 기계

```
intro ─(0.4 s 뒤 탭 / 자동 3.9 s)→ ready ─(탭)→ jump ─(착지)→ boost(2.2 s 무료 추력) → fly
fly ─(목표 파괴)→ escape(최대 7 s, 조종 가능) → done(정산·결과)
fly ─(실패 후보)→ fail(유예 1.0 s → 확정, 2.4 s 뒤) → done
일시정지·나가기 → abandon() → done(결과 화면 없음, 주운 병뚜껑만 정산)
```

| 상수 (`END`, `JUMP`) | 값 | 의미 |
|---|---|---|
| `failGrace` | 1.0 s | 실패 후보 뒤 이 시간 안에 목표가 무너지면 성공이 이긴다. 지나면 원장이 닫힌다 |
| `failHold` | 2.4 s | 실패 확정 → 결과 화면 |
| `escapeTime` | 7 s | 성공 뒤 퇴장 플레이 시간. 이 안에 빠져나가면 보너스 |
| `escapeDist` | 16 m | 실내 구역이 없는 무대에서 '빠져나감'으로 보는 목표와의 거리 |
| `settleAfterEscape` | 1.2 s | 퇴장 성공 뒤 결과까지 |
| `JUMP.crouch / air` | 0.32 s / 1.05 s | 널뛰기 동작 |
| `JUMP.ringFrom / perfectFrom` | 0.35 / 0.75 | 링 표시 시작 / **초록 = 완벽 판정 구간**(같은 상수, R-02) |

규칙
- 같은 물리 단계에서 목표 파괴와 로켓 파괴가 겹치면 **목표가 이긴다**(`resolveEnd`).
- `done`에서는 물리·픽업·타이머가 더 이상 갱신되지 않는다(R-04). `world.ledgerOpen=false`이면 픽업과 목표 판정이 원장을 바꾸지 않는다.
- 일시정지는 `canPause()`(intro·ready·jump·boost·fly·escape)에서만 열린다. 결과·실패 확정 뒤에는 열리지 않는다(R-01).
- 정산은 시도 번호(`save.attempts`)당 한 번만 일어난다(`save.lastSettled`). 결과 버튼 연타·재시도·앱 종료가 이중 지급을 만들지 않는다.

## 2. 성공·실패·퇴장 계약 (Q-AH-08)
- 성공 = 목표 엔티티 파괴. 원인(공략)은 아래 §4로 정한다.
- 퇴장은 **보너스**다(필수 아님): 실내 구역(`StageDef.escapeZone`)이 있으면 그 상자를 벗어나고 목표에서 6 m 이상, 없으면 16 m 이상. 보너스 = max(50, 무대 보상 × 25%).
- 퇴장 중 로켓이 부서져도 성공은 유지되고 보너스만 없다. 퇴장 중 일시정지·나가기는 성공 정산(퇴장 보너스 없음)으로 끝난다.
- 실패 사유: 추락(무대 아래), 로켓 파손(마지막 피해 재질·속도 포함), 연료 소진 후 정지(연료 0 + 속도 0.8 미만 1.4 s 또는 연료 0 상태 20 s). 연료통을 주우면 소진 타이머는 처음부터 다시 잰다(R-03).
- 실패 화면은 원인 + 다음 시도 팁을 보여준다(`describeDeath`).

## 3. 입력 계약 (C-016~C-027)
- 유동형 조이스틱: 누른 곳이 기준점, 끈 방향 = 분사 방향, 로켓은 반대로 가속. 데드존 7 px, 최대 출력 거리 64 px ÷ 감도(32~110 px).
- 주 포인터 하나만 조종한다. 두 번째 손가락·손바닥은 무시. `pointercancel`·창 blur·일시정지·화면 전환에서 입력을 놓는다(stuck thrust 0).
- 메뉴·HUD 버튼 위의 터치는 비행 입력이 되지 않는다(버튼은 `#touch` 위 레이어, 일시정지 버튼은 pointerdown 전파 차단).
- 탭/Space/Enter는 **눌린 순간(edge)** 한 번만 행동이 된다. 누르고 있어도 반복되지 않는다(R-02).
- 키보드(데스크톱 시험용): 방향키/WASD = 가속 방향.

## 4. 원인(공략) 판정 계약 (R-06)
- 로켓이 직접 부숨 → `ram`. 단, **로켓이 거의 멈춰 있고 상대가 더 빨리 움직여 부딪힌 경우**(떨어진 목표가 서 있는 로켓에 닿음)는 ram이 아니다 → 상대의 연쇄 원인 또는 `topple`.
- 부서진 물체가 받치던 것들은 그 원인을 물려받는다(`propagateHint`, 깊이 8, 접촉으로 연결). 직접 들이받아 지지대를 부순 경우 받치던 것은 `topple`.
- **정적 구조물(바닥·벽)은 원인을 전달하지 않는다.** 바닥을 친 것이 방 전체에 원인을 퍼뜨리지 않는다.
- **먼저 움직이게 한 연쇄가 소유한다**: 원인 힌트는 4 s 동안, 또는 그 물체가 계속 움직이는 동안(최대 30 s) 유지되고, 다른 연쇄가 덮어쓰지 않는다. 폭발이 이미 움직이는 대상을 부숴도 원래 연쇄가 이긴다.
- 폭발은 동적 물체에만 원인을 심는다. 물이 밀어낸 물체는 `water`. 밧줄 절단은 밧줄에 정해진 원인(`device` 기본, 무대에서 지정 가능)을 매달린 물체에 준다.
- 무대에 등록되지 않은 원인으로 성공하면 일반 이름(`GENERIC_METHOD`)으로 표시하고 공략 배지는 주지 않는다.
- 결과 화면·공략 배지·보상·소문(힌트)은 모두 같은 `cause` 값을 쓴다.

## 5. 물리 (C-028~C-039)
- 고정 60 Hz 단계, 렌더 보간. 프레임이 느려도 한 프레임 최대 5단계(그 이상은 버림 — 장시간 정지 복귀 시 순간이동 방지).
- 기수 방향 추력: 원하는 방향으로 회전 속도·회전 가속 제한 안에서 돌고, 추력은 정렬도에 비례(최소 15 %).
- **끼임 방지(C-038)**: 추력을 명령하는데 속도 0.45 m/s 미만·회전 정지가 0.35~0.8 s 이어지면 드래그 방향으로 작은 도약을 준다. 로켓 상태가 NaN이 되면 마지막 정상 위치로 복구한다.
- **재현성(C-039)**: 게임 결과에 영향을 주는 난수는 (무대, 시도 번호) 시드의 스트림에서 나온다(`seedGame`). 같은 입력 → 같은 난장판. 화면 효과만 `Math.random`.
- 2.5D: 모든 충돌은 z=0 평면. 시각적 깊이는 Q-CI 규칙(`docs/visual-contract.md`)을 따른다.

## 6. 합법 기체 (C-033, C-196)
- 324개 조합 중 추력/무게 ≥ 1 이 합법(현재 267개). 불법 조합은 차고에서 조립은 되지만 **출격이 막히고** 이유와 "가볍게 고쳐줘"(보유 부품만 쓰는 최소 변경 `autoFixLoadout`)를 보여준다.
- 추력/무게 1.0~1.15는 경고만 한다. `tests/parts.test.ts`가 324개 전부를 검사한다.
